# Codex Game Studios

**把一个游戏想法，变成有策划、有数值、有 UI 方案、有验收依据的开发流程。**

Codex Game Studios 是面向 **Codex** 的游戏开发工作流框架。
你用自然语言说出目标，工作室总控根据已有资料安排角色和步骤，
从创意探索、玩家定位、系统设计，到技术方案、开发、测试与复核持续推进。
**不需要逐个输入技能命令，也不需要安装 Claude Code。**

本项目是 [Donchitos / Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios)
的**非官方衍生适配**。原项目的角色、工作流、规则与模板构成基础；
本仓库增加 Codex 入口、内部流程衔接和可恢复的进度账本。保留原作者版权与 MIT 许可。

## 为什么做这个项目

和 AI 一条条聊天改游戏，很容易变成：有需求就加代码，数值随手填，
界面各做各的，修一个问题又影响另一个系统。

这个项目把相关工作放进同一条流程：
**先弄清玩家体验与规则，记录系统依赖和数据，再实现并保留验证证据。**

你负责方向、取舍和试玩反馈；Codex 负责组织工作、保存决策和执行当前目标。
它是辅助制作的工作室流程，不是保证一键生成好游戏的引擎。

## 你可以从任何阶段开始

| 你的情况 | 工作室怎么开始 |
|---|---|
| 完全没有具体想法 | 了解偏好、目标玩家与制作条件，提出可比较的方向 |
| 有一个模糊点子 | 明确游戏类型、核心循环、平台和范围，规划验证原型 |
| 已经有策划文档 | 整理已确定规则、冲突、数值缺口与待决策内容 |
| 有原型或现成代码 | 检查现状，接续有效成果，补齐必要设计与验证 |
| 只想修一个问题 | 路由到相关设计、实现和回归检查，不重走整套制作流程 |

引擎与技术选择要服从目标平台、团队经验和性能要求；已有选择会保留。
资料涵盖 **Godot、Unity、Unreal**，但本适配尚未对三种引擎完成逐一端到端实测。

## 怎样推进

~~~mermaid
flowchart LR
    A["描述目标 / 提供资料"] --> B["总控判断现状与范围"]
    B --> C["策划 · 数值 · UI · 技术方案"]
    C --> D["分阶段实现"]
    D --> E["测试 · 观察 · 复核"]
    E --> F{"当前目标完成？"}
    F -->|未完成| D
    F -->|完成| G["交付与进度记录"]
    C -.关键选择.-> H["用户决策"]
    H --> C
~~~

原制作流程保留七个阶段：
**概念 → 系统设计 → 技术准备 → 预制作 → 正式制作 → 打磨 → 发布准备**。

总控按项目规模与当前目标选择路线。仅策划、仅评审、原型或小修复都可以有边界；
不会因为有七个阶段就强行把每个请求做成商业游戏发布。

## 快速开始

1. 点击本仓库 **Use this template** 创建自己的项目，或克隆后建立自己的远程仓库。
2. 在 Codex 中打开项目根目录，即包含 **AGENTS.md** 的目录。
3. 直接描述目标，例如：

> 我想用 Godot 做一款生存防守游戏，目前只有一个模糊想法。
> 请按工作室流程带我推进：先确定目标玩家、核心玩法和合理规模，
> 再整理系统、数值经济、UI 与技术方案。需要我决定方向时再问我。

或者：

> 这是我的策划文档和现有代码。请先检查冲突和缺口，
> 然后按工作室流程完成一个可以试玩的核心循环。

后续只需正常交流。“继续”会依据保存的进度恢复。
**75 个技能是内部工具，不是要求用户逐个操作的菜单。**

### 环境要求

- 可读取项目指令与技能、编辑文件和执行工具的 Codex。
- Python **3.10+**：用于本地流程账本与校验，脚本只依赖标准库。
- Git；使用保留的 Bash 辅助工具时需要 Bash，Windows 可用 Git Bash。
- 真正制作和运行游戏时，需要相应游戏引擎及必要的运行/观察工具。

无需为本框架配置额外的 Claude 账号或模型 API key。
Codex 本身仍使用你自己的账号、权限与额度。

## 包含什么

| 部分 | 内容 |
|---|---|
| 工作室总控 | 自然语言入口、内部选步骤、衔接与恢复 |
| 角色说明 | 49 个专业角色，涵盖策划、经济、UI、引擎、程序、QA 等 |
| 工作流 | 74 个原项目工作流，加 1 个 Codex 总控技能 |
| 规则与资料 | 14 组规则、原项目文档模板及引擎专项资料 |
| 进度账本 | 当前目标、步骤、阻塞问题、验收记录与证据哈希 |
| 完成检查 | 缺少证据或存在待决问题不能通过；证据变更需要复查 |
| 开发维护 | 可重复生成适配文件、结构校验、离线测试和 GitHub Actions |

49 个角色是职责与提示词，**不等于同时运行 49 个 Agent**。
允许且支持时可用 Codex 原生子代理；顺序角色审阅会注明为自审。

## 验证与当前边界

已在本地通过：

- **32 项离线测试**：步骤衔接、已有项目接续、设计范围、中断恢复、
  失败阻塞、证据失效、修复插入、归档和生成保护。
- 统一入口支持 Hook 覆盖审计、完整门禁、技能目录和事件调度。
- **75 个技能格式检查**，**105 处阶段引用检查**。
- 独立解压包重新运行校验与测试。

这些是流程、状态和结构验证，**不是已经用本框架完整制作并试玩游戏的证明**。
自然语言路由、设计质量和全部 74 个工作流的实际效果仍需持续验证。

还需要了解：

- 原版 15 个 Claude 事件 Hook 的项目级职责已由 `tools/ai/hooks.py` 和
  `tools/ai/guard.py` 提供等价入口；Codex 私有的事件传输和通知 UI 仍由主机负责。
- 自动衔接发生在正在运行的 Codex 任务中；关闭会话后不会在后台无限开发。
- 缺少运行或观察工具时，游戏验收必须明确标为未验证。
- 引擎、素材质量、经济平衡和游戏乐趣仍需实际制作、模拟与试玩。

详见 [验证记录](docs/ai/VALIDATION.md) 和 [兼容说明](docs/ai/COMPATIBILITY.md)。

## 项目结构

~~~text
AGENTS.md                  Codex 默认入口
.agents/skills/            74 个工作流入口 + 工作室总控
ai/                       适配后的角色、工作流、规则与资料
.claude/                  保留的上游来源；不是 Codex 的执行配置
docs/ai/                  总控协议、状态格式与验证记录
tools/ai/                 转换、校验、进度账本
tests/adapter/            离线流程测试
design/                   游戏设计产物
production/               制作计划与进度记录
src/                      游戏代码位置由引擎配置决定
~~~

## 开发与贡献

python tools/ai/export-universal.py --check
python tools/ai/validate.py
python -m unittest discover -s tests/adapter -v
